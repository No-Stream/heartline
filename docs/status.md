## What works

The game runs in the browser from `make build` and `make serve`, with a deterministic Rust simulation in a web worker and a custom instanced WebGL2 renderer. A toolbar switches between Watch, Coaster, Paths, Landscape, Facilities and Scenery, each with one panel in the print-modern art style. The world is a layered isometric map (512 by 512 supported) with sculpted terrain, water, tunnels, caverns and an underground view. Paths are laid by dragging, follow slopes, store explicit edge connections and include queue paths that belong to a specific ride. Facilities cover the park entrance, food and drink stalls, restrooms, a souvenir shop, a carousel and a ferris wheel, with prices and revenue tracked. Scenery comes in Garden and Woodland sets, including lamp posts that light up at night.

Coasters are built piece by piece in the builder panel, with ink icons for each piece, steppers, keyboard shortcuts, a camera that follows the open end, and a test run. The chain lift is a toggle (button above the palette, key H) that puts a chain on any ordinary piece the model's lift rules allow; every turn has climbing and descending versions, so lifts can curve, and Timber Tumbler and Velocity Viper have 60-degree lifts and drops (Briar Blitz stops at 45). Players set an entrance fee and a ticket price per coaster, the Watch bar has a game-speed control (x1 to x16, key V), and Export session (key J) downloads a file of every command and checkpoint that the replay tests can play back. Three models exist, each with its own piece list and a playful manufacturer name: Timber Tumbler by Rocky Road Construction (inspired by RMC hybrids), Velocity Viper by Impulse Engineering (Intamin launch coasters) and Briar Blitz by Great Coaster Workshop (GCI wooden twisters, with a steel-structure loop allowed and purely wooden loops refused). Track pieces are curves with continuous curvature across joins and mirrored right-hand versions, and every banked turn leans into its curve. Physics runs at 200 Hz with rider-frame g-forces, rollback recovery and launches. Test runs give excitement, intensity and nausea ratings, friendly notes, a speed and g-force ribbon on the track, and proximity events (near-misses, headchoppers, dueling, tunnels, terrain hugging). Automatic block sections let several trains run without collisions.

Guests are individuals with correlated traits, groups and relationships, needs, personal knowledge of the park, utility-based decisions, bounded memories and thoughts. They walk shared flow fields across levels, queue, board coasters in groups, feel their car's forces and remember the ride. Clicking any guest, including a rider, opens their details. Sprites match each guest's age and appearance from a cast of 18 designed people, including Woody the thoosie. The day-night cycle lasts 24 real minutes, with a print-style colour grade, night lights, fireworks, crest confetti and a sky.

## Performance so far

Run `make check` for the fast tier: it builds the game, runs representative Rust unit tests (including the builder flexibility checks and a small set of seeded builder walks), application and art Vitest tests, TypeScript typechecking, and Playwright tests tagged `@fast` (including the session replays). Run `make journeys` for the player-journey tests, which play the game through the real UI in live mode; `make e2e-slow` for the longer flows tagged `@slow`, including the frame smoothness check on the production build; `make ci` runs everything, with the full builder walk matrix in release mode. The test strategy and its reasons are in `docs/superpowers/plans/2026-11-03-flexible-track-and-gameplay-tests.md`. The fast tier assumes dependencies and the Rust/WebAssembly toolchain are already installed. Always set a free `PLAYWRIGHT_PORT` when several agents run browser tests; the config never reuses a running server.

On the owner's RTX 5090, the renderer drew 10,000 animated people with terrain and track in about 2.6 ms of GPU work per frame. In the browser worker on one thread, 10,000 guests take about 7 ms per simulation tick; natively on 4 threads, about 2 ms, with identical results at any thread count. The full-scale performance check with a realistic large park on real hardware has not been done yet (ticket TASK-26).

## Known gaps and open items

- The owner's first playtest bugs (TASK-42, 45, 46, 47, 48) are fixed, and the owner's second playtest found a dead end building a chain lift on Timber Tumbler. Its exact cause was never reproduced; the likely causes were the missing climbing turns (now added) or a panic during choice validation that stops the worker (fixed in f4044c4). The builder (TASK-37) and its palette (TASK-70) are waiting on the owner's next playtest. The park still resets when the dev server reloads (TASK-49, after saving exists).
- The coaster stutter was the renderer interpolating from snapshot arrival time while frames cost 35-40 ms; it now interpolates on simulation time. Per-frame scene rebuild cost is still high (TASK-59), and on this WSL machine software WebGL takes about 350 ms per frame, so smoothness is best judged in the owner's browser.
- The Timber Tumbler player journey (TASK-65) plays the loop to guests paying but is not yet committed: rider clicking fails and it runs 5-7 minutes against a 3-minute budget. The Velocity Viper and Briar Blitz journeys (TASK-73) and pruning tests the journeys cover (TASK-75, TASK-76) come after it.
- One full-suite run produced an all-black canvas in a construction screenshot (TASK-62); the renderer now recovers from WebGL context loss, but that failure was not reproduced.
- Broader coaster vocabularies with signatures and manufacturer styles remain in TASK-43; the flexible-track plan took over its turns, chain lifts and 60-degree parts.
- Remaining code health refactors: typed worker protocol (TASK-57), `main.ts` around a shared tool interface (TASK-58), typed coaster and block state (TASK-55), shared helpers (TASK-52), projection and renderer stages (TASK-59).
- Not started: saving and loading, the full-scale performance check, public deployment, sound, scenarios, touch input and a desktop wrapper.
- Simplifications worth knowing: ride loading is instant; building and ride clearance assume heights of 4 m and 12 m; automatic block placement searches generated brake positions within a budget, and throughput excludes loading time.
