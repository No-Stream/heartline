## What works

The game runs in the browser from `make build` and `make serve`, with a deterministic Rust simulation in a web worker and a custom instanced WebGL2 renderer. A toolbar switches between Watch, Coaster, Paths, Landscape, Facilities and Scenery, each with one panel in the print-modern art style. The world is a layered isometric map (512 by 512 supported) with sculpted terrain, water, tunnels, caverns and an underground view. Paths are laid by dragging, follow slopes, store explicit edge connections and include queue paths that belong to a specific ride. Facilities cover the park entrance, food and drink stalls, restrooms, a souvenir shop, a carousel and a ferris wheel, with prices and revenue tracked. Scenery comes in Garden and Woodland sets, including lamp posts that light up at night.

Coasters are built piece by piece in the builder panel, with ink icons for each piece, steppers, keyboard shortcuts, a camera that follows the open end, and a test run. The chain lift is a toggle (button above the palette, key H) that puts a chain on any ordinary piece the model's lift rules allow; every turn has climbing and descending versions, so lifts can curve, and Timber Tumbler and Velocity Viper have 60-degree lifts and drops (Briar Blitz stops at 45). Players set an entrance fee and a ticket price per coaster, paint each coaster's track, supports and trains from a palette of twelve inks in the builder panel (each model has its own default scheme, stored in the simulation's coaster state), the Watch bar has a game-speed control (x1 to x16, key V), and Export session (key J) downloads a file of every command and checkpoint that the replay tests can play back. Four models exist, each with its own piece list and a playful manufacturer name: Timber Tumbler by Rocky Road Construction (inspired by RMC hybrids), Velocity Viper by Impulse Engineering (Intamin launch coasters), Briar Blitz by Great Coaster Workshop (GCI wooden twisters, with a steel-structure loop allowed and purely wooden loops refused) and Daisy Dash by Windmill Ride Works (junior family coasters: a curving tyre-driven lift, 45-degree drops at most, two family hills, turns banked for 16 and 20 m/s, no inversions, ten two-seat cars and riders from 100 cm, so children can ride). Horizon Hawk by Boulder & Marlin (steel hyper coasters: a straight 45-degree chain lift, a wide 60-degree first drop, 20 × 128 m and 24 × 160 m floater camelbacks, turns banked for 16 to 32 m/s, no inversions or launches, eight four-across cars). The models are registered in one list (`coaster_models()`), which also generates the builder's model dropdown. Track pieces are curves with continuous curvature across joins and mirrored right-hand versions, and every banked turn leans into its curve. Physics runs at 200 Hz with rider-frame g-forces, rollback recovery and launches. Test runs give excitement, intensity and nausea ratings, friendly notes, a speed and g-force ribbon on the track, and proximity events (near-misses, headchoppers, dueling, tunnels, terrain hugging). Automatic block sections let several trains run without collisions.

Guests are individuals with correlated traits, groups and relationships, needs, personal knowledge of the park, utility-based decisions, bounded memories and thoughts. They walk shared flow fields across levels, queue, board coasters in groups, feel their car's forces and remember the ride. Clicking any guest, including a rider, opens their details. Sprites match each guest's age and appearance from a cast of 18 designed people, including Woody the thoosie. The day-night cycle lasts 24 real minutes, with a print-style colour grade, night lights, fireworks, crest confetti and a sky. Night is a dark slate-blue print in which path lamps, lit stalls and flat rides throw two-band pools of warm light that relight the ground and buildings beneath them, and coasters stay partly floodlit so their colours read after dark.

## Performance so far

Run `make check` for the fast tier: it builds the game, runs representative Rust unit tests (including the builder flexibility checks and a small set of seeded builder walks), application and art Vitest tests, TypeScript typechecking, and Playwright tests tagged `@fast` (including the session replays). Run `make journeys` for the player-journey tests, which play the game through the real UI in live mode; `make e2e-slow` for the longer flows tagged `@slow`, including the frame smoothness check on the production build; `make ci` runs everything, with the full builder walk matrix in release mode. The test strategy and its reasons are in `docs/superpowers/plans/2026-11-03-flexible-track-and-gameplay-tests.md`. The fast tier assumes dependencies and the Rust/WebAssembly toolchain are already installed. Always set a free `PLAYWRIGHT_PORT` when several agents run browser tests; the config never reuses a running server. Every make recipe and every `npm run e2e` runs inside one shared resource budget for the whole project (`tools/run-in-budget.sh`: a user cgroup slice that throttles at 16 GB and stops at 20 GB; inside the Codex sandbox, which cannot reach the user systemd bus, a watchdog kills a command's process tree past 20 GB instead), so parallel agents cannot freeze the machine; browser test runs also wait for each other, one at a time. All build and test compute runs on six cores, one thread per core (`tools/compute-cpus`, applied by `tools/run-pinned.sh`, the cargo `rustc-wrapper` in `tools/rustc-budget.sh` with four compile slots, and a cargo runner for test binaries), so bare `cargo` calls are bounded too; feature browser tests use two workers and journeys one. Builds and tests refuse to start with under 25 GB free on the project's disk (`tools/require-free-disk.sh`, called by the budget script and the rustc wrapper), and debug builds keep only line tables (about 0.8 GB per worktree instead of up to 7 GB); after merging a branch, run `cargo clean` in its worktree. Run browser tests only with `npm run e2e -- <playwright args>` or a make target: the Playwright config refuses to start otherwise. While editing, run only the tests relevant to the change, and run the full gate at checkpoints such as before a commit.

To regenerate the Timber Tumbler built-session fixture through the build journey and the Export session button, run `RECORD_JOURNEY_SESSIONS=1 PLAYWRIGHT_PORT=4950 npm run e2e -- web/e2e/journeys/timber-tumbler.journey.spec.ts --project journey --workers=1` after `make build`.

On the owner's RTX 5090, the renderer drew 10,000 animated people with terrain and track in about 2.6 ms of GPU work per frame. In the browser worker on one thread, 10,000 guests take about 7 ms per simulation tick; natively on 4 threads, about 2 ms, with identical results at any thread count. The full-scale performance check with a realistic large park on real hardware has not been done yet (ticket TASK-26).

## Added on 2026-11-04

The builder panel has Build, Colours and Operate tabs, with every way of choosing the next piece on Build. Finish coaster stays available whenever its bounded search finds a connection (within 80 m and five pieces) and says why when it cannot. A short half-tile S-bend helps close circuits near the station. Coaster track carves tunnels automatically when it goes below ground, and undo restores the terrain. Each launch has an adjustable target speed limited by launch technology (1.5 g sustained, 240 km/h, and the launch's length). The game can be paused with Space or the clock button, which also freezes the rendered frame, and the game bar fits itself to the window by hiding parts in a fixed order. A master volume and mute control (key M) and the audio engine core exist, but no sounds play yet. The ground grid is clearer while a building tool is open, night lamp light fades smoothly, and surface lights no longer show in the underground view. The underground view can also show a cutaway window instead of cutting the whole view: a circle that follows the end of the track being built (cut just above it) or the pointer (at the chosen cut level), with coaster track buried outside the window traced through the ground as a flat silhouette. Trains now coast onto chain lifts instead of snapping to lift speed, which removed a 286 g force spike.

## Added on 2026-11-05

Inversions, drops and 60-degree pieces are force-limited (TASK-95): forces are measured at the rider's heart, elements are designed from force targets by a profile solver, embedded as tables, and each has a rated entry-speed window checked with full trains. The builder shows a live estimate while building (TASK-105): the unfinished track is coloured by how close the worst force is to the model's limit, sparse labels rate notable moments (weak, good, great, too much, dangerous), hovering shows every value, and launches show their maximum speed and force. Selecting an element preselects the size that suits the entry speed and previews its forces (TASK-123). Large quarter turns come banked for 16, 20 or 24 m/s (the bank follows the curve so riders feel no sideways force at that speed; Briar Blitz stops at 20): from a predicted entry speed of 12 m/s a turn step picks the size whose window holds the speed, the Bank stepper has a "For speed" position between level and the 45-degree bank so the player can go back to a level turn, and every turn previews its forces (TASK-101). New pieces: banked straights and roll-outs (TASK-102), 14 force-designed airtime hills (ejector, floater, speed hill, wooden ejector), 22 outer-banked hills, zero-g rolls and stalls, wave turns and a rated overbanked turn (TASK-101 tasks 1-4), a rated Briar Blitz top hat and a Velocity Viper launched top hat (TASK-98). Inversions are grouped as heartlined (modern) and classic in the builder (TASK-111), and players choose cars per train in Operate (TASK-127). Parks save in the browser and export and import as files from a Park menu (TASK-25). The underground cutaway turns on automatically when building below ground, with an Auto/Off/On control (TASK-116). Sound plays: building and interface sounds (a placement thunk by material, undo, error, a finish flourish), train sounds (roar by material, chain clack, launch, brakes, station), rider screams, crowd murmur, and day birds and night crickets (TASK-28; the owner's listening pass is pending). Keyboard input made while the builder is busy is queued instead of dropped (TASK-120), the page and game bar read Heartline (TASK-117), and the crowd and operating journeys no longer depend on machine speed (TASK-124).

## Added on 2026-11-06

The game's own coasters are force-designed rides now: Timber Tumbler (about 8.2 excitement), Velocity Viper (6.7) and a rebuilt demo (5.1) stay inside every force limit, using turns banked for their speed (16 to 32 m/s, bank chosen by the builder by default) so sideways force becomes positive force. Chain lifts pull the whole train until its last car is off. Two new models: Daisy Dash, a family coaster for riders from 100 cm (about 3.7), and Horizon Hawk, a B&M-style hyper with 20 x 128 m and 24 x 160 m camelbacks (about 6.7). Positive force is rated by absolute g ("great" from 3 g on steel, 2.5 g on wood and family). Models live in one registry. The builder updates about four times faster natively. CI runs browser tests in the pinned Playwright image, and world sprites are drawn as indexed triangles, which halves frame time in software WebGL. Builds refuse to start under 25 GB free disk.

## Added on 2026-11-18

Clicking a coaster's track, supports or train in Watch mode opens a ride window, and the builder has a Ride info button next to Test coaster. The window shows the model, the three scores, the reasons for them, the grouped statistics and a graph of vertical, lateral and forward g and speed over ride time with the model's force limits as bands; pointing at the graph highlights that moment on the track. The latest test report per coaster is kept in the simulation (the demo coaster's in `demo_report`, the player's coaster's in `construction_report`, which now survives opening the coaster), so it is saved with the park and cleared when the track changes. A coaster without a current report shows a Test button that runs the test at once without animating it.

## Added on 2026-11-19 to 2026-11-22

The project now includes the command-line design tool (`tools/design`), which drives the same `BuilderSession` as the browser to build, test, check force headroom and rated margins, search circuit finishes (`finish` / `finish apply`), and run fast Node/WASM browser-path agreement checks. Simulation math now uses portable `libm` calls (enforced by Clippy) so native and WebAssembly builds match across platforms, and GitHub CI runs green across sharded Rust, web, and Playwright jobs (TASK-118). Autosaves with rotating slots (TASK-129) and the concise score breakdown (TASK-130) are live.

Player-built coasters are now judged by a single ASTM F2291-based force-and-duration comfort envelope rather than per-model score penalties (TASK-166, save format version 6). Per-model limits are stored as `DesignForceTargets` for showcase-ride checks, rated feel edges, and shaped-element defaults; classic pieces expose both a hard ASTM rated window (red warning) and an inner model-feel edge (amber note, no score penalty). Shaped airtime hills and fully banked turns now run on a modular per-model `ShapedProfile` across all five coaster models—Horizon Hawk, Velocity Viper, Timber Tumbler, Briar Blitz, and Daisy Dash—with typical defaults inside each model's design targets and flexibility to push up to the global comfort envelope with a mild amber feel note (TASK-167). Finish search places shaped banked turns on every model. Horizon Hawk (one short mid-course brake run, sustained -0.94 g airtime), Briar Blitz (TASK-162), and Daisy Dash (five shaped floater hills, three shaped banked turns, passing `designMargins: true` under both physics configurations) have been rebuilt and verified with full browser agreement.
