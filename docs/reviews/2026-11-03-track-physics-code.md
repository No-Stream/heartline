# Track and physics code review

Reviewed committed code at `34e728092e1e35b327e0a80f12dd514062a5f9a5`. The working tree was changing during the review; the findings refer to committed files. The main maintenance cost is that geometry, validation, search and runtime operation cross module boundaries without a single clear owner for several shared concepts. Existing tests cover substantial behavior, but large files and repeated fixtures make it harder to find and extend that coverage. Sizes below are rough implementation estimates, including focused tests; no tests were run for this read-only review.

## Findings, ranked by day-to-day impact

1. **Split track geometry, catalog and model profiles by responsibility.** `crates/sim/src/track/mod.rs:16` defines geometry primitives, `:349` implements curves, `:601` starts a large catalog and `:1429` defines models; the file is 1,783 lines. Catalog variants are derived by cloning and mutating other pieces (`:1247`, `:1355`), while model factories maintain long piece lists (`:1466`, `:1563`, `:1669`). A change to a piece or model requires navigating unrelated curve math and data. Move curve primitives and evaluation, catalog definitions and mirrored generation, and model profiles into separate modules with existing public re-exports. Preserve the current mirrored generation and add or retain catalog and model regression tests; only share profile lists where the relationship is meaningful. **Medium.**

2. **Give block layout, search and operation clearer boundaries.** `crates/sim/src/track/blocks/mod.rs:250` builds candidates, `:461` advances manual search, and `:909` and `:1119` validate layouts through physics; the module is 1,241 lines. Runtime operation separately implements section lookup and station positioning (`crates/sim/src/physics/block_operation.rs:40`), with corresponding calculations in layout validation (`crates/sim/src/track/blocks/mod.rs:1119`, `:1201`). Extract pure layout and section-boundary calculations as the shared authority, then separate candidate generation, search and simulation-based validation. Keep validation using the real operation so the runtime remains the behavioral authority. Test wraparound and exact boundaries from both callers. **Large, but separable into several medium changes.**

3. **Replace block search's string-based control flow with typed outcomes.** Manual search matches an error message at `crates/sim/src/track/blocks/mod.rs:483`; automatic search matches two strings and discards other errors at `:695`. Capacity timeouts instead produce a successful layout with an incomplete flag (`:909`, `:1112`), so the capacity-error match appears unreachable in the committed implementation. Message edits can silently change search behavior, and an invalid candidate is hard to distinguish from an inconclusive trial. Introduce typed validation errors and an explicit incomplete outcome, convert to user-facing text at the boundary, and test invalid, timed-out and successful searches. Check callers before removing any public variants. **Medium.**

4. **Make support geometry and terrain sampling owned by their respective modules.** Construction duplicates support placement assumptions: its search region samples spacings `4.0` and `8.0` (`crates/sim/src/track/construction/mod.rs:594`), and it constructs train/track obstacle bounds itself (`:638`). Support generation owns its routing rules and dimensions (`crates/sim/src/track/supports.rs:34`, `:113`, `:382`). Changes to support spacing or footprint can therefore require a coordinated construction edit. Also, terrain triangle interpolation is repeated in supports (`:545`, `:602`) and proximity (`crates/sim/src/track/proximity/mod.rs:350`). Expose a support-owned conservative search region and obstacle conversion, and extract a world-surface interpolation helper that also supports the brace calculation's chosen triangle. Retain collision and terrain boundary tests. **Medium.**

5. **Check the geometry reuse key for mirrored inversions.** Construction reuses a previous choice's validation result when `same_geometry` matches (`crates/sim/src/track/construction/mod.rs:129`, `:557`), but the comparison omits the piece's `mirrored` field. The catalog generates mirrored corkscrew and heartline pieces (`crates/sim/src/track/mod.rs:1352`, `:1362`); curve evaluation uses the mirrored flag. **Hypothesis:** if such a pair has equal compared fields and arc tables but different paths, an asymmetric obstacle could make the reused result wrong. Add a realistic asymmetric-obstacle regression that compares choice results with individual validation; if reproduced, include orientation in the key or replace the comparison with an explicit geometry identity. **Small to medium.**

6. **Decompose train operation and make input errors consistent.** `Train::new` checks user-supplied configuration with assertions and `expect` (`crates/sim/src/physics/mod.rs:201`), while `Circuit::new` returns a string error (`:25`). `BlockOperation::step` combines reservation, movement prediction, collision checks, report positioning and completion handling (`crates/sim/src/physics/block_operation.rs:199`). Extract a few private operations around these responsibilities, and introduce typed construction errors for invalid circuit and train configurations, updating callers deliberately. Keep assertions for internal invariants. Exercise invalid inputs and existing multi-train behavior. **Medium to large, independently landable.**

7. **Organize tests around behavior and share only repeated setup.** Production `block_operation.rs` is followed by inline tests (`crates/sim/src/physics/block_operation.rs:345`), while powered-hold and station tests are separate files; both repeat catalog lookup and state advancement (`crates/sim/src/physics/block_operation/powered_hold_tests.rs:4`, `crates/sim/src/physics/station_block_tests.rs:4`). Support and clearance files also contain hundreds of lines of inline tests (`crates/sim/src/track/supports.rs:692`, `crates/sim/src/track/clearance.rs:453`). Move related tests into named neighboring test modules and share a small circuit builder where it preserves scenario clarity. Block validation simulates up to 600 seconds at the physics time step (`crates/sim/src/track/blocks/mod.rs:909`), so document which integration tests exercise that search and why before considering any runtime changes. **Medium.**

8. **Name rating parameters and remove dead error states.** Rating thresholds have names, but the rating formula embeds numerous calibration values (`crates/sim/src/physics/testing.rs:380`, `:392`); grouping named constants or a documented rating profile would make tuning and review easier without changing scores. `SupportError::SearchExhausted` is declared and mapped (`crates/sim/src/track/supports.rs:25`, `crates/sim/src/track/construction/mod.rs:571`), but no production path constructing it was found in the reviewed track code. Verify all callers, then remove it or implement a meaningful distinct outcome. Preserve score regression tests. **Small.**
